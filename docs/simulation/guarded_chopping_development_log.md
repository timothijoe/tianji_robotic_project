# 双臂猫爪倒手切菜开发日志

日期：2026-07-31
分支：`feature/left-wuji-pick-place`

## 2026-08-01：消除 Viewer 启动旧场景闪现

用户观察到每次启动时会先出现通用举刀姿态、红色方块、绿色目标区和两个灰色
底座，随后才突然切换到正确切菜姿态。排查确认模型中没有重复生成垃圾物体；根因
是 `RightArmRobot(viewer=True)` 在 guarded-chop 预检、场景隐藏和 ready reset
之前就打开了 passive Viewer，首屏因此显示通用模型默认状态。

修复后机器人提供幂等 `open_viewer()`，原有 `viewer=True` 调用保持兼容；
guarded-chop 则先以 headless 方式创建机器人，完成预检、场景配置、双臂与 Wuji
Hand 初始状态以及 `mj_forward` 后才开窗、设置相机并创建轨迹 trace。预检失败时
不会闪现窗口，headless 路径也不会调用 Viewer。现有 `GUARD_READY` 阶段在窗口
打开后保持正确初始姿态，便于观察砧板和刀手位置。

最终完整仿真回归为 187 项通过，另有一条既有接触力观测 warning。两次真实
Viewer 启动均完成 5 刀、4 次倒手和 0.080 m 总退让，最小刀手距离 0.039 m，
均返回 `success=True`；首帧视觉效果交由用户最终确认。

用户第三次查看 Viewer 首帧后确认“这次挺好的”，同意先按该版本合并。

## 2026-08-01：低刀位退手与斜向换刀

人工观察上一版“右刀回升/横移与左手倒手同步”的动作后，确认真实需求并不是
双臂同周期横移，而是有明确因果顺序的循环：右刀下切并落定，左手先倒手，随后
右刀再换位。因此默认 `plane` 状态机最终调整为：

1. `CUT_DOWN`：右刀下切并等待实际速度稳定。
2. `LOW_GUARD_OPEN`、`LOW_GUARD_SHIFT`、`LOW_GUARD_CLOSE`：右刀保持低刀位
   和固定目标，Wuji Hand 开手、左臂后退 0.02 m、重新合手。
3. `GUARD_SETTLE`：右刀继续锁定，等待左臂和手指稳定。
4. `KNIFE_LIFT_SHIFT`：左手锁定，右刀用一条斜向笛卡尔轨迹同时抬升和横移，
   连续衔接下一刀安全起点。

安全复审补充了四项边界保护：物体场景在横移前检查实际刀刃高度；平面退手轨迹
的每个预检采样都必须保持刀手距离单调不减；`GUARD_SETTLE` 也强制右刀静止；
斜向轨迹通过全路径 minimum-jerk 修正匹配下一下降阶段的精确关节端点，并在修正
后重新验证速度和加速度。四条斜向轨迹最大速度约 0.115 rad/s、最大加速度约
0.578 rad/s²，低于项目 2 rad/s 和 10 rad/s² 的限制。

最终完整仿真回归为 184 项通过，另有一条既有接触力观测 warning。平面和物体
无窗口运行都完成 5 刀、4 次倒手和 0.080 m 总退让，最小刀手距离分别为
0.039 m 和 0.062 m，均返回 `success=True`。用户连续两次查看 Viewer 后确认
动作效果“很不错”，同意合并该版本。

## 2026-08-01：默认平面演示

`guarded-chop` 现在默认使用 `plane` 场景，在砧板平面上从屏幕右侧向左侧
完成 5 刀和 4 次倒手。每次换位都明确经过 `HAND_OPEN`、`HAND_SHIFT`、
`HAND_CLOSE`，即开手、后退 0.02 m、重新合拢；总目标位移仍为 0.08 m。

Viewer 用蓝线显示右刀规划路径、青线显示右刀实际轨迹、紫线显示左手护手
实际轨迹，并保留 5 个紧凑的 cut marks。命令入口为：

```bash
.venv/bin/twin-sim guarded-chop
.venv/bin/twin-sim guarded-chop --headless --final-hold 0
.venv/bin/twin-sim guarded-chop --scene object
```

`--scene object` 保留下面记录的固定红色方块接触标定，作为回归场景；它不再
是默认演示。两个场景都只运行 MuJoCo，不会连接或控制实体机械臂、ROS 或
Wuji Hand SDK。

## 目标

右臂持刀对固定方块演示 5 次下切，左臂和 Wuji Hand 以猫爪姿态护住方块，
每次右刀抬起并到达下一刀安全位后，左手后退 0.02 m。阶段 A 使用确定性
状态机；阶段 C 只预留 `SafetyCoordinator` 接口。

## 实现记录

1. 增加默认隐藏、无关节的固定红色方块；任务启动时只在当前 MuJoCo 模型
   实例中显示它，并隐藏抓取放置使用的自由方块、绿色目标区和两个灰色台。
2. 在 Wuji Hand 中指第二指节增加 `left_guard_knuckle_site`，作为刀手距离的
   几何参考点。
3. 增加 20 关节 `CAT_PAW_RAD`：拇指向掌内收，另外四指的近端与远端关节
   弯曲，形成半握拳护手姿态。
4. 复用巡线切菜的刀具姿态和横向切点，但将整条刀轨迹提高到固定方块顶部，
   避免沿用砧板高度后把刀硬压入方块。
5. 左手使用独立左臂 IK 生成 4 段笛卡尔倒手轨迹；右刀下切时左手目标锁定，
   左手倒手时右刀目标锁定。
6. 初版只检查护手 site，复审实测发现其他手指仍会碰刀。最终安全距离取旋转
   刀片到所有命名手部碰撞代理的最小几何距离，并单独要求刀片—手部真实
   接触数始终为零；site 只负责可视化护手轨迹。
7. 增加蓝、青、紫、黄四类 Viewer marker，以及刀数、阶段、距离和许可状态
   overlay。
8. 最终接触诊断发现初始护手点悬在方块上方，没有真实手—方块接触。将护手
   高度降到方块范围内，并显式更新任务方块 body 的碰撞聚合掩码后，集成测试
   要求至少出现一个真实 MuJoCo 手—方块接触点。
9. 安全复审发现仅检查左臂 7 轴速度仍可能让手指在下切期间运动。互锁现同时
   检查 Wuji Hand 的 20 个关节速度范数；猫爪接触固定方块后锁存实际关节
   姿态为新的位置目标，消除原目标持续推入方块造成的接触抖动，并连续稳定
   0.3 秒后才允许下切。
10. 接触复审进一步发现所有手指碰撞体都与固定方块配对时，第四次倒手会把
    小指/无名指侧向压入约 17.65 mm，法向力约 149 N。任务现在用独立碰撞位
    只允许中指指垫与方块接触，其他手指仍参与刀手碰撞检测；倒手期间逐周期
    锁存手指位置并把 2 cm 换位延长到 3 秒。安全协调器同时限制指垫穿入不超
    过 3 mm、法向力不超过 35 N，超过任一限制立即中止。

## 已解决问题

### 原切菜轨迹会进入固定方块

原 `line-chop` 以砧板表面作为接触高度；固定方块高 0.10 m，直接复用会让
刀具穿过方块。预检现在按“方块顶面－砧板顶面”整体抬高刀轨迹，并增加
小量跟踪余量。方块仍为刚性固定物体，不实现切分或变形。

### TCP 距离不能代表刀手安全距离

刀具 TCP 位于刀柄/工具坐标处，与刀面有明显偏移。安全协调器现在把护手点
变换到 `right_knife_blade` 的局部坐标，计算到旋转 box 表面的最近距离。

### 双臂移动许可容易混在一条轨迹中

状态机明确分成 `CUT_DOWN`、`KNIFE_UP` 和 `HAND_SHIFT`。右刀在
`KNIFE_UP` 中先抬起并横移到下一刀安全位；随后右臂保持目标，左手才执行
倒手。这样阶段 C 可以替换许可策略而不重写轨迹。

## 验证与限制

定向测试 29 项通过；全量测试 143 项通过，仅保留一条既有切菜接触力 warning。
无窗口集成运行完成 5 刀、4 次倒手，总目标位移 0.08 m，实测最小刀手距离
不低于 0.020 m；实体机保护哈希全部通过。Viewer 首次逐控制周期刷新 overlay，
导致播放耗时数分钟；将文本和 marker 一并降采样到每 10 个控制周期后，完整
动作、3 秒结尾保留和正常退出约 50 秒完成，返回 `success=True`。

当前限制：方块固定且不会变形；猫爪会与方块真实接触，接触后锁存实际姿态
继续使用位置保持，但不依赖接触力闭环；
刀手保持几何间隙，不模拟第二指节贴刀面；阶段 C 的实时误差恢复和导纳控制
尚未实现；所有命令仅用于 MuJoCo。

## 2026-08-01：1× 在线录制与 2× 状态回放

在不改变 MuJoCo 控制时间和安全逻辑的前提下，新增了类似简化版 rosbag 的状态录制
与回放路径。`./scripts/run_guarded_chop.sh` 继续只显示一遍 1× 在线仿真；新增的
`./scripts/run_guarded_chop_record_replay.sh` 先执行并观看同一遍 1× 在线仿真，再在
同一 Viewer 中按记录时间戳以 2× 回放。回放状态栏带有 `replay 2.0x` 标识。

录制帧包含 MuJoCo `time`、`qpos`、`qvel`、`ctrl`，以及 phase、cut index、刀刃点、
护手点、累计最小距离和下切许可。数组在捕获时复制并冻结，避免 MuJoCo 后续原地更新
污染旧帧。2× 回放逐帧恢复状态并调用 `mj_forward`，不调用 `mj_step`，也不重新执行
关节位置控制器、安全协调器或接触求解，因此不会产生第二套仿真结果。

`--record` 是可选项。裸参数保存到 `recordings/guarded_chop_latest.npz`；同一路径通过
临时文件加 `os.replace` 原子覆盖，避免重复文件和半写入文件。显式指定其他文件名时
才保留多个版本。NPZ 使用 schema version 1，并在加载时校验当前模型的 `nq/nv/nu`。

验证覆盖了不可变帧、NPZ 往返、维度拒绝、纯状态回放、marker 重建、CLI、两个 shell
入口及完整仿真回归。最终结果为 `202 passed`，仅保留一条既有的 39.611 N 接触力
观测告警。默认录制连续执行两次后仍只有一个 latest 文件；显式命名后两个文件并存。
实测记录各包含 3115 帧，末帧 phase 为 `complete`。组合 Viewer 和从 latest 文件直接
进行的 2× 回放均成功，任务指标保持 5 刀、4 次倒手、0.080 m 总退让和 0.039 m
最小刀手距离。

本轮开发直接提交到 `develop_9_kinematic_branch`，没有额外的临时 feature 分支需要
合并。关键提交从 `bd3e314`（状态录制）到 `cffa447`（验证记录）。

## 2026-08-01：两刀循环的自然猫爪倒手

针对旧版每刀固定“整手张开—左臂平移—整手闭合”的机械感，默认平面场景改为两刀
一个循环的 inchworm 步态。第 1、3 刀后左臂 7 关节目标严格不变，中央 `finger3`
指垫主导回缩；第 2、4 刀后左臂掌心后退约 4 cm，同时手指从回缩姿态恢复为较宽松
但仍紧凑的猫爪。四次指垫净推进仍各约 2 cm，公共结果继续报告 4 次倒手和 0.080 m。

Wuji 资产没有可靠的拇指/食指解剖学标签，因此代码按编号实现：`finger3` 变化最大，
相邻 `finger2` 次之，`finger4`、`finger5` 逐级减小，`finger1` 保持内藏。确定性 FK
标定得到的回缩姿态在掌心固定时使 `left_finger3_pad` 后退约 2.12 cm，非目标方向
漂移约 2 mm。旧 knuckle site 不再用于紫色轨迹，但仍保留在模型中；刀手安全距离
始终计算刀片到全部手部碰撞代理的最小值。

预检为四次动作生成 `[finger_retract, arm_reset_relax, finger_retract,
arm_reset_relax]` 配对轨迹。全部手指使用 minimum-jerk；偶数周期的左臂和手指轨迹
样本数一致并同步发送。右刀低位期间继续锁定目标并监控实际速度。全手距离在偶数动作
初段只有不足 0.9 微米的几何数值波动，局部单调校验使用 2 微米数值容差，2 cm 硬
安全下限和运行期接触判断均未放宽。

完整自动回归为 `207 passed`，另有一条既有 39.611 N 接触力观测告警。真实 1×
Viewer 完成 5 刀、4 次逻辑倒手和 0.080 m 总推进，最小刀手距离为 0.054 m，返回
`success=True`。程序验收通过；手指层次和两刀循环的人工观感等待用户确认。

本轮实现方案 A（离线标定的手指协同轨迹）。方案 B（在线 20 关节手指 IK）和方案 C
（人工关键帧库）继续保留在设计文档中，未进入运行时代码。
