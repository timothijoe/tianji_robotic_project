# A 臂关节阻抗两阶段播放器设计

## 目标

提供一个仅针对 SDK A 臂的命令行工具，以关节阻抗方式完成两个阶段：

1. 从启动时读取的 A 臂实际关节角，在 20 秒内平滑接入 `recordings/recorded_hand_guarded_chop_200hz_official_right_retarget_candidate.npz` 的 `left_arm_target_rad[0]`。
2. 以 0.1× 速度读取同一字段的后续轨迹点，并逐点发送关节阻抗目标。

## 运行模式

默认是只读计划模式，不发送任何状态或运动命令。只有显式传入 `--execute` 才考虑执行。

执行模式在当前阶段必须拒绝运行，除非独立碰撞预检成功。当前 MuJoCo 场景因不支持的 XML `compiler conflict` 属性无法加载，因此该条件尚不成立。工具不提供绕过该条件的开关。

## 前置检查

执行前必须：

- 连接指定控制器并连续确认 A 臂反馈帧在更新；
- 确认 A 臂 `err_code == 0`；
- 从反馈读取 A 臂实际七关节角，作为接入段起点；
- 校验来源 NPZ 的 `left_arm_target_rad` 为有限的 `(N, 7)` 数组；
- 校验每一个接入和播放目标均在明确配置的关节限位内；
- 确认控制器没有由其他程序占用，并由现场人员确认工作空间与急停可用；
- 成功完成离线碰撞预检。

任何一项失败均不使能、不下发轨迹。

## 阻抗和时间行为

播放器只使用关节阻抗：`state=3` 和 `impedance_type=1`。K/D 取值必须显式显示并通过 CLI 参数提供，默认值以当前控制器读取到的参数为准但不得静默覆盖。

接入段采用五次平滑插值，20 秒、200 Hz、两端静止。播放段使用来源轨迹的相邻时间差除以 0.1，原始 5 ms 间隔对应 50 ms 墙钟间隔。每次命令后读取反馈；帧停滞、非零错误、实际与目标的最大关节误差超过配置阈值、限位违规或收到 Ctrl+C 都触发终止。

## 停止策略

发生终止时，程序停止后续点下发，尽力将 A 臂切至 `state=0`，然后释放 SDK 连接。它不清除故障、不复位伺服、不改变 B 臂或 Wuji 手的状态。

## 验证

以单元测试验证 NPZ 校验、时间计划、接入端点、限位/误差拒绝和执行前碰撞许可门。任何真机测试必须先由用户完成现场检查和预检，并显式调用 `--execute`。

## 非目标

- 不控制 B 臂、右手或 Wuji 手。
- 不清除控制器错误。
- 不允许跳过碰撞预检、关节限位或实时反馈检查。
- 不在当前版本执行真正的抓取动作；在仿真碰撞预检恢复前，执行模式保持拒绝。
