# MuJoCo 原生位置控制仿真重建设计

日期：2026-07-30

## 1. 背景

当前仓库使用 MuJoCo `motor` 力矩执行器，并在 Python 中维护
`UnifiedController`。现有 `POSITION` 模式实际上也是关节 PD/阻抗控制，
Cartesian impedance 和 force control 则包含更多控制律、限幅、滤波与调参逻辑。
这些实现与实体机器的控制行为并不等价，却占用了大量仿真开发精力。

本次重构把 MuJoCo 仿真的主要职责收敛为：

1. 验证机器人模型和 Viewer。
2. 验证关节位置运动。
3. 验证 Cartesian 目标的 IK 与运动路径。
4. 执行一次右臂切菜轨迹。
5. 记录接触力并观察定性趋势。

仿真不再尝试复现实体机器的阻抗控制。实体机器人代码、厂商 SDK、动态库和配置
暂时保留，不修改控制行为，也不在本轮验证。

## 2. 目标与非目标

### 2.1 目标

- 使用 MuJoCo 原生 `position` actuator 取代仿真侧自研关节和 Cartesian 阻抗控制。
- 将 Cartesian 目标转换为连续的 IK 关节轨迹，再交给位置执行器跟踪。
- 保留 MuJoCo 动力学、碰撞和接触力计算，使接触力具有定性趋势。
- 建立 Linux 上可从零创建的项目内 `.venv`，锁定 Python 与直接依赖版本。
- 彻底重建仿真目录与 API，不保留旧仿真接口兼容性。
- 将被替换的旧仿真代码放入仓库内 `archive/legacy_simulation/`。
- 建立只描述新仿真的文档目录。
- 用自动化测试和 headless smoke demo 验证五项核心能力。

### 2.2 非目标

- 不校准仿真接触力，使其数值与实体机器一致。
- 不实现 Cartesian impedance、joint impedance 或 force control。
- 不在本轮实现导纳控制。未来导纳控制只作为修改位置目标的上层模块。
- 不迁移旧 replay、全量轨迹演示或其他旧仿真功能。
- 不保证旧仿真 API 或脚本继续运行。
- 不连接、运行或验证实体机器人。
- 不修改厂商 SDK 调用、参数语义或动态库。
- 不保证 Windows 仿真环境。

## 3. 技术方案

### 3.1 选择的控制方案

机器人关节采用 MuJoCo 原生 `position` actuator。执行器的 `kp`、阻尼、
速度约束和输出限制属于模型配置，不作为应用层阻抗 API 暴露。

主要控制链路为：

```text
Cartesian/关节任务目标
        ↓
Cartesian 路径采样（仅 Cartesian 命令）
        ↓
连续 IK
        ↓
带时间参数的连续关节位置轨迹
        ↓
MuJoCo position actuator
        ↓
状态、接触力、Viewer 与 CSV
```

不采用以下方案：

- 保留 `motor` 并维护极简 PD：仍会使项目承担控制器设计和调参职责。
- 每周期直接写 `qpos`：绕过动力学，无法满足接触力趋势要求。

### 3.2 接触行为

切菜阶段按照预设位置轨迹下压，到固定深度后停留并抬起。接触力不参与位置目标
修正。力超过配置阈值时：

- 打印 warning；
- 在 CSV 中记录阈值状态；
- 继续执行原定轨迹。

若 MuJoCo 状态出现 NaN、Inf 或其他数值异常，则立即停止。力阈值警告与数值异常
属于不同级别，不能混用。

接触力只要求满足定性趋势：刀具接触并继续下压时，滤波后的接触力总体增加；
抬刀脱离接触后，接触力回落。不要求具体牛顿值与实体机器一致。

## 4. 仓库与模块架构

目标目录结构如下：

```text
project/
├── simulation/             # 新 MuJoCo 仿真主线
│   ├── model.py
│   ├── robot.py
│   ├── kinematics.py
│   ├── trajectory.py
│   ├── force_monitor.py
│   ├── logging.py
│   ├── cli.py
│   └── tasks/
│       └── chop.py
├── real_robot/             # 实体机器人代码；本轮冻结
├── robot_assets/           # 模型、mesh 与场景资产的单一副本
├── examples/               # 少量新仿真入口
├── tests/                  # 新架构测试
├── docs/
│   └── simulation/
├── vendor/                 # 厂商 SDK、动态库和配置
└── archive/
    └── legacy_simulation/
```

最终目录名可在实施计划中根据现有 Python 打包约束细化，但职责边界不得改变。
模型、mesh、厂商 SDK 和大型二进制文件只保留单一副本，不复制进归档。

### 4.1 模块职责

#### `model.py`

- 加载 MuJoCo 模型和场景。
- 校验必需的关节、position actuator、TCP site、接触对象与传感器。
- 提供稳定的模型对象名称映射。

#### `robot.py`

- 提供右臂关节状态读取。
- 向 position actuator 写入关节位置目标。
- 推进 MuJoCo、同步 Viewer，并检测数值异常。
- 不包含阻抗、力矩或导纳控制公式。

#### `kinematics.py`

- 提供 FK、Jacobian 与 IK。
- 仅使用 SI 单位：rad、m、s。
- 不包含厂商 SDK 风格的单位和参数兼容。

#### `trajectory.py`

- 生成带速度、加速度约束的连续关节轨迹。
- 对 Cartesian 路径逐点采样并连续求解 IK。
- 校验关节范围、有限值和相邻点跳变。

#### `force_monitor.py`

- 读取原始接触力。
- 提供可配置的低通滤波输出。
- 判断阈值状态并产生 warning。
- 不改变运动目标。

#### `tasks/chop.py`

- 编排一次“接近、下压、停留、抬刀”任务。
- 只调用轨迹、机器人和日志接口，不实现底层控制律。

#### `logging.py`

CSV 至少记录：

- 时间和任务阶段；
- 目标与实际关节位置；
- 目标与实际 TCP pose；
- 原始与滤波接触力；
- 力阈值和 warning 状态。

#### `cli.py`

提供稳定入口：

- 模型和 Viewer；
- 关节位置运动；
- Cartesian IK 运动；
- 单次切菜。

## 5. 数据流

单次切菜执行流程：

1. 加载并校验模型。
2. 读取机器人初始状态。
3. 根据场景几何生成接近、下压、停留和抬刀路径。
4. 对整条 Cartesian 路径采样。
5. 在执行前对所有采样点连续求解 IK。
6. 校验完整关节路径并做时间参数化。
7. 每个控制周期写入 position actuator 目标并执行 MuJoCo step。
8. 读取实际关节、TCP 和接触力。
9. 写入 CSV；超力阈值时 warning 但不中断。
10. 抬刀到安全高度并正常结束。

若任一 Cartesian 采样点 IK 失败、相邻关节解跳变过大或目标越界，整条轨迹在执行
前失败，机器人不得开始运动。

## 6. 环境设计

- 使用仓库根目录 `.venv`。
- 基准解释器为 CPython 3.12；minor 版本写入版本标记文件，环境文档要求
  `python3.12`。
- 锁定 MuJoCo、NumPy、pytest 等直接依赖的精确版本。
- 提供统一的环境创建、安装、测试和示例命令。
- `.venv`、运行日志和生成 CSV 加入 `.gitignore`。
- Conda 只提供安装失败时的备用说明，不维护独立依赖清单。
- 验收环境只覆盖 Linux；Windows 和实体 SDK 不在本轮运行范围。

环境建立后，先运行旧系统当前可运行的测试和代表性示例并记录基线，再移动或重写
文件。旧系统中已经失败的测试必须记录原因，不能被误报为本次重构回归。

## 7. 归档与迁移

### 7.1 归档原则

被替换的旧仿真模块、示例、对应测试和过期仿真文档移动到
`archive/legacy_simulation/`，并尽量保留原相对层次。

归档目录包含 `README.md`，记录：

- 归档日期；
- 归档前 Git commit；
- 原入口和依赖；
- 停止维护原因；
- 查阅或恢复方式。

归档代码：

- 不作为可安装 Python package；
- 不加入 `PYTHONPATH`；
- 不参与 pytest；
- 不被新仿真模块导入。

### 7.2 新文档

`docs/simulation/` 包含：

- `setup.md`：Linux `.venv` 创建与依赖安装；
- `architecture.md`：新仿真模块职责和边界；
- `usage.md`：四个稳定入口的使用方法；
- `migration.md`：旧功能与新功能的对应关系。

迁移关系至少明确：

| 旧功能 | 新状态 |
|---|---|
| Cartesian impedance | Cartesian 路径采样、IK、position actuator |
| Joint impedance | MuJoCo position actuator |
| Force control | 仅力监控；导纳控制延期 |
| Replay 和全量轨迹演示 | 归档，不迁移 |
| 实体 SDK 接口 | 保留，不修改 |

### 7.3 迁移顺序

1. 创建 `.venv` 并记录旧系统基线。
2. 建立归档目录并移动旧仿真文件。
3. 建立新仿真模块和独立模型入口。
4. 运行新测试和 smoke demo。
5. 核对实体相关文件未发生内容变化。
6. 更新根 README，指向新文档和归档说明。

## 8. 错误处理与保护边界

- 缺少必需模型对象时，启动失败并列出缺失名称。
- 输入维度错误、非有限值、关节越界或非法时间参数时，轨迹生成失败。
- IK 失败或路径跳变超过配置上限时，执行前失败。
- 日志路径不可写时，运动开始前失败。
- Viewer 被关闭时，循环正常退出并释放资源。
- 接触力超过阈值时 warning 并继续运动。
- MuJoCo 状态为非有限值时立即停止。
- 本轮禁止连接或运行实体机器人。
- 新仿真模块禁止导入实体 SDK。
- 实体 SDK、动态库、配置和调试代码在迁移前后使用内容哈希核对。
- 因目录移动必须调整实体代码路径时，应单独列出并获得确认；默认不移动实体代码。

## 9. 测试设计

### 9.1 模型测试

- 模型可以加载。
- 14 个关节存在。
- 右臂 7 个 position actuator 映射正确。
- TCP site、接触对象和力传感器存在。

### 9.2 运动学测试

- FK 输出有限。
- IK 能回解已知可达姿态。
- 不可达目标明确失败。
- 连续 Cartesian 路径不存在异常关节跳变。

### 9.3 轨迹测试

- 起点与终点正确。
- 时间严格单调。
- 位置、速度和加速度连续。
- 所有关节目标处于范围内。

### 9.4 机器人接口测试

- position actuator 能跟踪关节目标。
- 最终实际误差处于测试定义的容差内。
- headless 测试不依赖 Viewer。
- Viewer 关闭后能够正常退出。

### 9.5 力监控测试

- 无接触时滤波力处于基线容差内。
- 接触后半段的滤波力中位数高于接触前基线中位数。
- 抬刀稳定后的滤波力中位数低于下压末段的滤波力中位数。
- 超阈值产生 warning 和 CSV 标志，但任务继续。

### 9.6 切菜任务测试

- 完成接近、下压、停留和抬刀阶段。
- 最终刀具位于安全高度。
- CSV 阶段记录完整。

### 9.7 隔离与保护测试

- 新仿真代码不导入实体 SDK。
- 归档目录不参与安装和 pytest。
- 实体 SDK、动态库、配置和调试代码内容哈希不变。

## 10. 验收标准

以下条件必须全部满足：

1. 新 `.venv` 能在目标 Linux 主机从零创建并安装锁定依赖。
2. 新架构自动化测试全部通过。
3. 模型/Viewer、关节运动、Cartesian IK、单次切菜和接触力日志均有清晰入口。
4. 三个 headless smoke test 可以运行：关节运动、Cartesian IK、单次切菜。
5. 单次切菜生成 CSV；接触后半段的滤波力中位数高于接触前基线，抬刀稳定后的
   中位数低于下压末段。
6. 力超过阈值时任务继续，日志中存在 warning 标志。
7. 新仿真代码不含自研 Cartesian/关节阻抗控制公式。
8. 实体机器相关文件未发生功能性修改。
9. 旧仿真可在 `archive/legacy_simulation/` 查阅，但不影响新安装和测试。

具体数值容差、位置执行器参数、轨迹时长和力阈值由实施计划先通过最小实验确定，
再固化为有理由、可重复的测试参数；它们不得作为运行时阻抗调参 API 暴露。
