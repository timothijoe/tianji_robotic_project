# Wuji 双手本地 MuJoCo 角度条控制器设计

## 目标

提供一个独立的本地桌面控制器，用 20 个以弧度表示的滑条实时控制 Wuji 左手或右手的
MuJoCo 姿态。该版本不依赖 ROS，不访问真机；但其目标角度接口应可在后续由真机 SDK
实现复用。

## 范围

- 支持官方一代 Wuji Hand 的左、右手 MJCF 模型切换；一次只加载并控制一只手。
- 按五指分组显示每指四个关节的滑条与实时数值。
- 滑条范围必须来自当前模型 position actuator 的 `ctrlrange`，单位为 rad。
- 拖动后在下一仿真周期写入 `data.ctrl`，并在 MuJoCo Viewer 中同步显示。
- 提供“张开手”复位；切换手型时也复位到该手安全张开姿态。左、右手分别维护
  明确的 20 维张开角度常量，加载模型时验证常量位于该手的控制范围内。
- 所有控制输入必须是 20 个有限数值，且在当前模型控制范围内。

不包括 ROS topic、RViz、录制回放、双臂、实体手连接或真实硬件指令。

## 架构

```text
桌面滑条面板
  -> 20 维 target_rad
  -> HandControlBackend.command(target_rad)
  -> MujocoHandBackend: data.ctrl[:] / mj_step / viewer.sync
```

`HandControlBackend` 是小型接口，负责暴露当前手的关节元数据、控制范围、目标写入、
仿真步进和关闭。初版仅实现 `MujocoHandBackend`。

未来的硬件实现保持相同的 20 维 rad 输入，但由适配器负责转换为 SDK 所需的 `(5, 4)`
数组并调用 `wujihandpy`。硬件适配器不属于本次交付，也不允许被本地 MuJoCo CLI
自动选择。

## 组件

1. 模型元数据：从加载的 MJCF 中按 actuator 顺序读取关节名、控制范围和默认张开姿态。
2. MuJoCo 后端：加载左右模型之一，验证目标，写 `data.ctrl` 并以模型 timestep 前进。
3. 控制面板：手型切换、五指分组滑条、弧度显示、张开复位和安全提示。
4. 运行循环：面板可用且 Viewer 打开时，以 MuJoCo timestep 同步输入、仿真与渲染；任何
   窗口关闭都应平稳退出并释放 Viewer。
5. CLI：新增一个明确命名的本地仿真入口，默认左手；`--hand left|right` 可指定初始手型。

## 数据与安全约束

- 目标向量形状固定为 `(20,)`，顺序为五指、每指四关节，且与当前 MJCF actuator 顺序一致。
- 不能依赖左右手相同的数值范围、关节轴方向或 actuator 名称；切换后须重新读取模型元数据。
- UI 控件限制在 `ctrlrange` 内，后端仍重复校验，以防编程调用绕过 UI。
- 本功能不含硬件依赖；禁止导入或调用 `wujihandpy`、USB 枚举、ROS 或网络接口。
- “张开手”只使用各模型范围内的显式默认姿态；左、右手不得共用未经验证的数值，
  也不得以零向量或控制范围中点作为假设。

## 验证

- 单元测试：左右模型均能加载；关节/actuator 数量为 20；范围有效；非法形状、NaN 和越界
  目标被拒绝。
- 行为测试：每手的合法目标会写入对应 `data.ctrl`；切换模型后不沿用上一手的范围或目标；
  张开复位落在当前模型范围内。
- CLI 测试：帮助信息、左右手参数和 headless smoke（若入口提供该选项）均可运行。
- 人工验收：拖动每个滑条时，Viewer 中对应手指关节实时变化；切换后模型、范围和手势均正确。

## 成功标准

用户可在不启动 ROS 的情况下启动本地程序，切换左/右手，并用 20 个受限角度滑条稳定、
实时地驱动 MuJoCo 中对应手的姿态。程序不连接任何真实硬件。
