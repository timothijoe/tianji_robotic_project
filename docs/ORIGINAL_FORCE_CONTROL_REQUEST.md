# MuJoCo 机械臂力控：原始需求与完整决策记录

## 1. 文档用途

本文档完整记录本次 MuJoCo 机械臂力控任务的原始诉求，以及需求讨论过程中逐项确认的设计决策。

它用于后续追溯“为什么这样设计”，不因当前代码实现变化而删除原始要求。

相关文档：

- [`FORCE_CONTROL_REQUIREMENTS.md`](FORCE_CONTROL_REQUIREMENTS.md)：整理后的正式需求规格；
- [`FORCE_CONTROL_USAGE.md`](FORCE_CONTROL_USAGE.md)：当前实现的运行和调用说明。

## 2. 最初提出的需求

希望在 `cook_ws` 中构建一个支持力控制的 MuJoCo 机械臂。

力控模式的实现可参考：

```text
/home/zhoutong/catkin_robotic_ws/cook_proj/TJ_FX_ROBOT_CONTRL_SDK
```

重点涉及：

```text
TJ_FX_ROBOT_CONTRL_SDK/contrlSDK100343001
TJ_FX_ROBOT_CONTRL_SDK/kinematicsSDK
TJ_FX_ROBOT_CONTRL_SDK/DEMO_PYTHON
```

期望研究：

- `contrlSDK100343001` 中的机器人状态、扭矩模式、阻抗模式和力控参数接口；
- `kinematicsSDK` 中的运动学、Jacobian 和关节力矩到末端 wrench 的映射；
- `DEMO_PYTHON` 中力控 Demo 的初始化、模式切换、参数设置、命令发送和反馈读取方式；
- 最终在 `cook_ws` 中提供类似的 MuJoCo 力控能力和 Python Demo 调用体验。

参考的典型厂商接口包括：

```python
robot.set_state(arm="A", state=3)
robot.set_impedance_type(arm="A", type=3)
robot.set_force_control_params(...)
robot.set_force_cmd(arm="A", f=10)
```

第一版不直接链接厂商 `.so`，而是在 `cook_ws` 内基于 MuJoCo 重新实现可测试的控制器。

## 3. 核心目标

需要实现：

1. 单臂七自由度机械臂的 MuJoCo 动力学仿真；
2. 机械臂使用关节力矩 actuator 驱动，而不是直接写入 `qpos`；
3. 支持末端力控制；
4. 支持笛卡尔阻抗、关节阻抗或力控模式中的至少一种稳定实现；
5. 在腕部增加六维力/力矩传感器；
6. 能够给定轨迹并较好地追踪；
7. 能够执行切菜形式的重复“落刀—起刀”轨迹；
8. 提供类似厂商 SDK 的 Python 高层调用接口；
9. 提供可视化、数据记录和定量验证手段。

## 4. 两类验收场景

### 4.1 静态恒力控制

机械臂从砧板上方开始：

1. 缓慢接近固定平面；
2. 检测工具和平面接触；
3. 建立例如 `10 N` 的目标接触力；
4. 稳定保持指定时间；
5. 记录目标力、实测六维力、末端位姿和关节力矩；
6. 最后安全回撤。

### 4.2 动态切菜轨迹

给定切菜形式的轨迹，机械臂需要重复执行：

```text
落刀 → 接触/施力 → 起刀 → 移位 → 再次落刀
```

同时验证：

- 非接触阶段的末端轨迹跟踪；
- 接触阶段的恒力控制；
- 位置控制和力控制之间的平滑切换；
- 多次重复执行的稳定性；
- 接触峰值和关节力矩安全性。

## 5. 第一版功能范围

逐项确认的第一版范围为：

- 单臂七自由度；
- 工具 Z 轴单方向恒力闭环；
- 全程以笛卡尔阻抗控制为基础；
- 接触后，将工具 Z 轴从位置阻抗切换为力控制；
- X、Y 和工具姿态继续执行笛卡尔位置/阻抗跟踪；
- 只实现垂直剁切；
- 不实现水平推切或拉切；
- 使用简化刚性探头；
- 使用固定、适度柔性的砧板接触模型；
- 不模拟蔬菜破裂、切断和刀具穿透；
- 优先实现独立 Python 控制库与 Demo；
- 第一版暂不封装 ROS 2 topic、service 或 action；
- 暂不链接厂商控制和运动学动态库。

## 6. 模型和六维传感器

### 6.1 基础机械臂模型

基础 MJCF 需要增加：

- 七个关节力矩 actuator；
- 各关节对应的力矩限制；
- 稳定的关节和 actuator 命名；
- 工具安装接口。

### 6.2 独立剁切场景

剁切功能使用独立场景文件，包含：

- 基础机械臂；
- 简化工具；
- 腕部六维力/力矩传感器；
- 固定水平砧板；
- 可调摩擦、接触刚度和阻尼。

这样不会把砧板和测试工具永久耦合进基础机器人模型。

### 6.3 简化工具

第一版工具采用参数明确的简化刚性探头：

- 圆柱形工具杆；
- 球形接触端头；
- 明确质量、惯量、尺寸；
- 明确工具中心点；
- 明确传感器安装截面。

控制稳定后可以替换为真实刀具或锅铲模型。

### 6.4 六维力/力矩传感器

六维传感器不能只是随意添加到 `Link7_L` 上。

要求在腕部和工具之间建立独立传感截面：

```text
Link7_L → force_sensor_body/site → tool_body → tool tip
```

MuJoCo 中使用配对传感器：

```xml
<force ... />
<torque ... />
```

组合为工具坐标系下：

```text
[Fx, Fy, Fz, Mx, My, Mz]
```

工具 Z 轴作为第一版受控力轴。

统一正方向语义：

```text
正目标力 = 工具沿自身 Z 轴压向接触平面
```

## 7. 反馈来源

第一版采用 MuJoCo 腕部六维传感器作为力控主反馈。

同时保留以下诊断路径：

```text
关节力矩 + Jacobian → 反算末端 wrench
```

反算值用于诊断和对照，不作为第一版控制主反馈。

## 8. 控制架构

### 8.1 总体控制链

```text
笛卡尔关键帧轨迹
→ 轨迹插值和阶段状态机
→ 末端位姿/速度误差
→ 笛卡尔阻抗与工具 Z 轴力控制
→ 期望末端 wrench
→ Jacobian 转置映射
→ 重力/科氏力补偿
→ 力矩限幅和变化率限制
→ 七个关节力矩 actuator
→ MuJoCo 动力学
→ 腕部六维传感器反馈
```

### 8.2 非接触阶段

非接触阶段全六维采用笛卡尔阻抗控制：

```text
wrench_cmd = Kx · pose_error + Dx · velocity_error
tau_cmd = Jᵀ · wrench_cmd + qfrc_bias
```

目标是跟踪末端位置和姿态轨迹。

### 8.3 接触阶段

接触阶段使用混合位置/力控制：

- 工具 X、Y：继续位置/阻抗跟踪；
- 工具姿态：继续姿态阻抗跟踪；
- 工具 Z：切换为恒力控制；
- 输入轨迹的 Z 值只作为下探趋势和最大深度约束，不要求接触后严格追踪。

最终统一通过：

```text
tau = Jᵀ · wrench + qfrc_bias
```

输出关节力矩。

### 8.4 为什么不是“IK 等于阻抗控制”

笛卡尔轨迹转换和阻抗控制是两个不同层次：

- 逆运动学用于从末端位姿目标求关节参考、初始姿态或验证可达性；
- 阻抗控制根据实时位姿、速度和力误差计算关节力矩。

第一版实时控制以笛卡尔阻抗力矩控制为主，不是简单把笛卡尔位置转换成关节位置后再直接写入模型。

## 9. 逆运动学要求

采用 MuJoCo 实时 Jacobian 和阻尼最小二乘法，不依赖厂商 `kinematicsSDK`。

要求包括：

- 奇异点阻尼；
- 关节限位回避；
- 最大关节速度限制；
- 工具姿态保持；
- IK 收敛检测；
- IK 失败时停止并报告原因。

厂商运动学 SDK 后续可作为结果对照。

## 10. 控制周期和轨迹插值

逐项确认的周期要求：

- MuJoCo 仿真步长：`2 ms`；
- 底层阻抗和力控制：`500 Hz`；
- 用户轨迹输入：`100 Hz`；
- 控制器内部将轨迹平滑插值至 `500 Hz`。

控制器还需要：

- 关节速度限制；
- 加速度或轨迹平滑限制；
- 力矩限制；
- 力矩变化率限制；
- 实际控制周期监测。

## 11. 轨迹格式和状态机

轨迹采用显式阶段标记的笛卡尔关键帧，每个关键帧包括：

```text
时间 + 工具位置 XYZ + 工具姿态 + 阶段标记
```

状态包括：

```text
APPROACH
DESCEND
FORCE_HOLD
RETRACT
SHIFT
```

使用显式阶段而不是完全依靠接触力猜测动作意图。

传感器反馈仍用于确认实际接触和安全状态。

### 11.1 单次剁切流程

```text
安全高度
→ 沿工具 Z 轴落刀
→ 接触检测
→ 建立目标力
→ 恒力保持
→ 沿原路径起刀
→ X 方向移位
→ 下一次落刀
```

### 11.2 默认轨迹参数

- 剁切次数：`5`；
- 安全高度：砧板上方 `80 mm`；
- 相邻落刀间距：`20 mm`；
- 下降速度：`50 mm/s`；
- 目标接触力：`10 N`；
- 恒力保持：`0.5 s`；
- 抬刀速度：`80 mm/s`。

参数必须支持 Python API 和命令行覆盖。

## 12. 接触检测与切换

要求使用接触阈值和滞回机制，避免模式抖动。

基本逻辑：

- `DESCEND` 阶段超过接触进入阈值后，进入 `FORCE_HOLD`；
- 接触进入阈值和退出阈值不同，形成滞回；
- 切换力控时清理或连续初始化积分器；
- `RETRACT` 阶段关闭力控制并恢复完整笛卡尔阻抗；
- 接触丢失时根据阶段重新搜索或安全回撤。

## 13. 力传感器标定

启动 Demo 后，在工具悬空且静止时自动去皮：

1. 连续采样 `1 s`；
2. 检查机械臂是否静止；
3. 检查是否存在接触或异常波动；
4. 计算传感器零偏；
5. 根据工具姿态补偿工具自身重力；
6. 输出补偿后的外部 wrench。

如果标定期间机械臂运动或发生接触，则拒绝进入力控。

## 14. Python API 需求

高层调用方式尽量接近厂商 SDK，但内部为独立 MuJoCo 实现。

预期接口：

```python
robot.set_cartesian_impedance(...)
robot.set_force_control_params(...)
robot.set_force_cmd(force_n=10.0)
robot.execute_chopping_trajectory(...)
robot.get_wrench()
robot.stop()
```

单位统一使用 SI：

- 位置：米；
- 角度：弧度；
- 力：牛顿；
- 力矩：牛顿米。

API 必须明确坐标系、单位和力方向，非法参数需要产生可诊断错误。

## 15. 安全保护

逐项确认的基础安全阈值：

- 最大下探距离：`50 mm`；
- 最大接触力：`30 N`；
- 接触建立超时：`2 s`。

还需要保护：

- 关节位置限位；
- 关节速度限位；
- actuator 力矩限位；
- 力矩变化率限制；
- IK 失败保护；
- 控制周期超时监测；
- NaN/Inf 检测；
- 用户终止或关闭 Viewer 后安全停机。

严重保护触发后：

1. 立即停止继续下压；
2. 关闭力控制并清理积分状态；
3. 在安全可行时沿工具 Z 轴回撤；
4. 记录故障原因和触发数据；
5. 当前 Demo 返回失败状态。

## 16. Viewer 和运行数据

第一版需要 MuJoCo Viewer，但暂不开发复杂 GUI。

终端低频显示：

- 当前轨迹阶段；
- 目标工具 Z 轴力；
- 实测工具 Z 轴力；
- 末端位置误差；
- 控制频率；
- 安全状态。

运行过程写入 CSV，至少记录：

- 时间戳；
- 当前状态机阶段；
- 目标和实际末端位姿；
- 目标和实际六维 wrench；
- 原始和补偿后的传感器数据；
- 关节位置；
- 关节速度；
- 关节控制力矩；
- 接触状态；
- 安全保护状态和故障原因。

结束后生成结果摘要和关键指标。

## 17. 第一版验收标准

### 17.1 功能标准

- 六维传感器能够输出工具坐标系下的 wrench；
- 工具悬空去皮后读数接近零；
- 静态恒力 Demo 能够建立并保持 `10 N`；
- 能够完成五次剁切循环；
- 非接触阶段能够跟踪笛卡尔轨迹；
- 接触和离开接触时模式切换稳定；
- Python API 和命令行 Demo 可运行；
- Viewer、CSV 日志和结果摘要可用；
- 安全保护可以测试触发。

### 17.2 定量标准

- 静态 `10 N` 恒力稳态误差不超过 `±1 N`；
- 恒力阶段无持续振荡；
- 非接触阶段末端轨迹位置 RMSE 不超过 `5 mm`；
- 每次接触峰值不超过 `30 N`；
- 关节力矩不超过模型限制；
- 五次剁切期间不触发非预期安全保护。

- 水平推切或拉切；
- 六个方向同时进行力控制；
